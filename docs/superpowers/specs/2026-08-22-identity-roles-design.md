# 特教平台：一人一号多角色（家长 / 老师）

日期：2026-08-22  
状态：已批准 → 实施计划已写 `docs/superpowers/plans/2026-08-22-identity-roles.md`  
前置：一期登录协议（`POST /auth/login` + `Clientid`）已可用；微信 `grantType=xcx` 会自动建家长；老师档案 `special_teacher` 已有可选 `user_id`，但后台未绑登录账号；自定义 admin 无角色管理页。

## 背景

小程序目前默认按家长登录：账号密码（实际是 `user_name`）+ 微信一键。注册页是空壳。老师只是后台资料卡，不能登录。后台没有「给人开关角色」的界面。

目标：一个手机号一个账号，可同时挂家长和老师；小程序能注册家长、手机号密码登录、微信一键登录；老师只能后台开通，两端都能进，但只看自己的资料和预约。

## 决策（已确认）

| 项 | 决策 |
|----|------|
| 路径 | 方案 A：一人一号，角色叠在 `sys_user_role`，`currentRole` 写在 Sa-Token 会话 |
| 账号键 | 手机号唯一；角色往上叠，不因开通老师/家长再建用户 |
| 注册 | 小程序/H5 只能开通家长：手机号 + 验证码 + 设密码 |
| 登录 | 小程序：手机号+密码 **和** 微信一键；H5：仅手机号+密码 |
| 微信无手机号 | 允许先登录（默认家长），进「我的」或预约前强制绑手机；号已存在则合并 |
| 验证码 | 小程序优先微信手机号快速验证；否则短信。H5 走短信。备案/签名未过：开发用测试码，生产未开短信则 H5 提示通道未开通 |
| 角色管理 | 后台只给人开关家长/老师，不建角色、不配菜单树 |
| 老师 PC | 能进后台，只看「我的资料」「我的预约」 |
| 老师小程序 | 切到老师后：老师首页摘要 + 自己的资料 + 收到的预约；底栏结构不改 |
| 切身份 | 「我的」里切换；本地缓存上次角色，冷启动默认进入 |
| 协议 | **不改** `POST /auth/login` 形态、`Clientid`、微信 xcx 协议 |
| UI | 主色 `#1B7F6B`；身份 Tag 必须有文字；可点区域 ≥ 44px |
| ID | 雪花 ID 全程字符串 |

## 明确不做（本 spec 范围外）

- 机构管理员 / 学校管理员的开通与登录
- 完整若依式角色 CRUD、菜单树、按钮权限配置页
- 老师排课、接单工作台、上课记录
- 短信登录作为主入口（`grantType=sms` 保留不用）
- 忘记密码完整流程（管理员可重置；短信签名过了再加验证码重置）
- 解绑微信页
- 为小程序再开一套页面树或第五 Tab
- 改登录协议或去掉 `Clientid`

## 1. 账号与角色

**一个手机号 = 一个 `sys_user`。** 不新增用户表。

| 角色 | `role_key` | 谁开通 | 业务资料 |
|------|------------|--------|----------|
| 家长 | `special_parent` | 小程序/H5 注册，或微信登录（默认） | 无独立表 |
| 老师 | `special_teacher` | 仅后台 | `special_teacher.user_id` → 该用户 |
| 平台管理员 | `superadmin` | 现有 admin | 无 |

`special_org_admin` / `special_school_admin` 本 spec 不赋、不登录、不管理。

### 叠角色（手机号当合并键）

- **注册 / 绑手机开通家长**：号不存在 → 建用户 + `special_parent`；号已在但无家长 → 只加家长；已是家长 → 去登录，不重复开通。
- **后台开通老师**：号不存在 → 建用户 + `special_teacher` + 老师档案 + 初始密码；号已在但不是老师 → 加老师角色并建/绑档案；已是老师 → 提示已存在。
- 同一用户可同时有家长和老师。不允许通过「取消角色」把用户变成零角色：至少留一个，否则用 `sys_user.status` 停用。

`user_name`：手机号注册/建老师时用手机号作为 `user_name`（与手机号相同，便于排错）。微信尚未绑手机的临时用户仍为 `wx_` + openid 后缀。

### 当前角色 `currentRole`

存在 **Sa-Token token 会话**，取值只能是该用户已有的 `special_parent` 或 `special_teacher`。

登录或冷启动恢复顺序：

1. 小程序本地缓存 `special_current_role` 仍属于该用户 → 用它  
2. 否则有家长 → 家长  
3. 否则老师  

退出登录时同时清 token 与角色缓存。

**PC：**

- `superadmin` 不走家长/老师切换，进全量工作台；即使该账号碰巧有老师档案，也不进入「只看自己」。
- 老师账号登 PC：会话 `currentRole` 固定为 `special_teacher`，无切换器。
- 仅家长登 PC：登录后拒绝进入后台业务（见 §5）。

### 微信绑定

`sys_social`：`source = WECHAT_MINI_PROGRAM`，`openid → user_id`。一个 openid 只能绑一个用户。绑手机时若手机号已有用户：把社交绑定和该临时号上的预约迁到目标用户，再停用临时 `wx_` 用户（`status` 停用，不物理删除）。openid 已绑其他用户再绑 → 报错，本 spec 不做解绑。

## 2. 登录、注册、绑手机、验证码

请求仍带与登录时一致的 `Clientid`：

- 小程序/H5：`special_xcx_client_id`
- PC：`e5cd7e4891bf95d1d19206ce24a7b32e`

### 小程序登录页

同一页两块，不拆流程：

1. **手机号 + 密码** → `grantType=password`。请求体字段仍叫 `username`，值为 11 位手机号。后端：11 位数字先查 `phone_number`，否则查 `user_name`（保证 `admin` 仍能用密码策略，但小程序 UI 不引导用户名）。
2. **微信一键**（仅 `#ifdef MP-WEIXIN`）→ 现有 `grantType=xcx`。
3. 链到注册页（只开通家长）。

H5 登录页：仅手机号 + 密码 + 去注册；无微信按钮。

登录成功后写入 `currentRole`（规则见 §1），小程序写入本地缓存。

### 注册（只开通家长）

表单：手机号 + 验证码 + 设密码。走 `POST /auth/register` 的扩展，**仅对小程序 client 开放**（PC 不开放自助注册）。成功后加 `special_parent` 并直接登录。

已有用户但无家长（后台先建的老师）：校验验证码后加家长角色；密码：若请求带了新密码则更新，否则保留原密码。

全局配置 `sys.account.registerUser` 不要对 PC 一刀切打开。实现上按 `clientId === special_xcx_client_id` 允许注册，避免管理员自助注册入口。

### 验证码通道

| 场景 | 通道 |
|------|------|
| 小程序注册 / 绑手机 | 优先微信「手机号快速验证」（`getPhoneNumber` 的 `code` 交后端换真号）；用户拒绝再用短信 |
| H5 注册 / 绑手机 | 短信（现有 `CaptchaController` 发码 + 限流） |
| 开发 / 短信签名未过 | 验证码写日志或固定测试码；**生产关闭测试码** |
| 生产短信未开通 | 小程序仍可用微信授权手机号；H5 注册/绑手机提示「短信通道未开通」 |

不把 `grantType=sms` 当这一期主登录入口。

### 微信绑手机

已微信登录且 `phone_number` 为空：浏览资源/机构不强制；进入「我的」敏感操作或提交预约 → 绑手机页。

拿到手机号后：

1. 该号无用户 → 写到当前用户，`user_name` 若仍是 `wx_` 可改为手机号（若手机号与其他 `user_name` 冲突则只写 `phone_number`）
2. 该号已有用户 → 合并到已有用户（社交绑定 + 预约 `user_id`），停用临时号，给目标用户签发新会话（前端换 token）
3. 合并时：目标用户若还没有家长角色，**加上家长**（用户主动绑手机并使用小程序，视为需要家长能力）

### 后台新建老师的第一次登录

管理员设初始密码并告知。老师可用：手机号+密码（小程序或 PC）；或微信一键后绑同一手机号走合并。

忘记密码：这一期管理员在用户角色页「重置密码」。

### PC 登录

仍 `grantType=password` + PC `Clientid`。平台管理员用原用户名；老师用手机号。

**仅有家长、没有 `superadmin` 也没有 `special_teacher` 的账号，用 PC client 登录时直接失败**，文案「无后台权限」，不签发 token。老师兼家长的账号可以登 PC，会话按老师「只看自己」。

### 失败文案

- 密码错：账号或密码错误（不暴露是否存在）
- 微信失败：登录失败，请重试
- 验证码错/过期：验证码无效
- 无家长且无老师：账号未开通
- 仅家长登 PC：无后台权限
- 绑手机 openid 冲突：该微信已绑定其他账号
- 切换没有的角色：当前账号没有该身份

## 3. 小程序体验

底栏仍为首页 / 资源 / 机构 / 我的。不新增 Tab。公开目录在老师身份下仍可看。

### 缓存与切换

- 本地键：`special_current_role`
- 冷启动有 token：用缓存调 `PUT /auth/current-role` 恢复；失败则按 §1 默认规则并改缓存
- 仅当用户 **同时拥有两个角色** 时，「我的」出现「切换身份」
- 资料卡用文字 Tag 显示 `家长` 或 `老师`
- 切换成功：写会话 + 写缓存，`switchTab` 到首页并刷新「我的」

管理员撤掉某一角色后：缓存若指向已失效角色，打开时回落到仍有效的角色并提示。

### 家长身份

首页保持现有搜索 / 四宫格 / 分类 / 资源卡片。「我的」：我的预约（`user_id = 自己` 且按家长视角）、关于、退出。

### 老师身份

- 首页：老师摘要（资料要点、待处理预约数、入口到收到的预约），**不**展示家长找课四宫格
- 「我的」：老师资料、收到的预约、切换身份（若有）、关于、退出
- 不能改自己的审核状态；未通过审核的老师档案不出现在公开老师列表（与现有审核一致）

### 登录页 UI

热区 ≥ 44px；主色 `#1B7F6B`；系统黑体。登录框文案为「手机号」，不再出现「如 admin」。

## 4. 管理后台

侧栏工作台不变，不改成顶栏主导航。登录后必须调用 `GET /system/user/getInfo`，按角色裁侧栏并做路由守卫。接口权限以后端为准。

### 谁能进

| 身份 | PC |
|------|-----|
| `superadmin` | 现有工作台 + 「用户角色」 |
| 有 `special_teacher`（非超管） | 仅「我的资料」「我的预约」；默认落到预约 |
| 仅 `special_parent` | 不能进后台 |

### 用户角色页（新，仅超管）

侧栏新增「用户角色」。列表：手机号、昵称、角色文字 Tag、账号状态。

- 勾选家长 / 老师；禁止两个都去掉  
- 勾选老师但无档案 → 引导补老师档案（手机号带入）  
- 取消老师：去掉角色，档案行保留，不能再以老师身份登录  
- 停用走 `sys_user.status`  
- 重置密码（仅超管）

家长 CRM 保持只读，不在该页改角色。

### 老师档案（超管）

现有 CRUD 增加：

- 新增必填 **手机号**；新建用户时必填 **初始密码**；手机号已有用户则不必设密码（可另点重置）  
- 保存走 §1 合并，写入 `user_id`  
- 列表增加「已绑账号 / 未绑」  
- **存量老师档案不自动建登录账号**；管理员补上手机号并保存后才可登录  

**登录角色** 与 **档案审核是否对家长可见** 分开：未过审老师可以登录改自己的资料，但不进小程序公开列表。

### 老师登录后的后台

1. **我的资料**：只编 `user_id = 自己` 的档案，不能改审核状态、不能改别人  
2. **我的预约**：只显示 `teacher_id` 指向自己档案的预约，可更新处理状态（沿用 0 待处理 / 1 已联系 / 2 已完成 / 3 已取消）

访问资源 / 机构 / 家长 / 审核 / 用户角色 / 全站概览 → 前端重定向到「我的预约」，后端 403。

### 预约如何挂到老师

当前 `special_appointment` 只有 `resource_id` + 申请人 `user_id`，**没有老师字段**。本 spec 增加可空列：

| 列 | 说明 |
|----|------|
| `teacher_id` | bigint，可空，指向 `special_teacher.id` |

- 从老师详情发起预约 → 写入 `teacher_id`  
- 从课程/机构/资源预约 → `teacher_id` 为空（仅管理员在全量列表可见）  
- 老师身份下列表 / 老师 PC「我的预约」= `teacher_id = 自己的档案 id`  
- 家长「我的预约」仍 = `user_id = 自己`  

合并微信临时号时，把临时用户 `user_id` 上的预约改到目标用户；`teacher_id` 不变。

## 5. 接口与权限

不改 `POST /auth/login` 的 client / grantType 约定。雪花 ID JSON 用字符串。

### 认证扩展

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | password 支持手机号；xcx 照旧；成功后写 `currentRole` |
| POST | `/auth/register` | 仅 xcx client；验证码 + 家长角色 |
| PUT | `/auth/current-role` | body `{ "roleKey": "special_parent" \| "special_teacher" }` |
| GET | `/system/user/getInfo` | 增加 `currentRole`、是否已绑手机、角色列表 |

### 小程序

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/special/mobile/me/bind-phone` | 微信手机号 `code` 或短信验证码；合并规则见 §2 |
| GET/PUT | `/special/mobile/me/profile` | 含 `currentRole`、角色、手机号 |
| GET | `/special/mobile/me/appointments` | 按 `currentRole` 分流 |
| GET/PUT | `/special/mobile/me/teacher-profile` | 仅老师身份，只编自己；不可改审核状态 |

未绑手机提交预约 → 拒绝。公开 ` /special/mobile/**` 列表仍 `@SaIgnore`。

### 后台

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/special/account/list` | `special:account:list` | 用户 + 角色 |
| PUT | `/special/account/{userId}/roles` | `special:account:edit` | 开关家长/老师 |
| PUT | `/special/account/{userId}/password` | `special:account:edit` | 重置密码 |
| 现有 | `/special/teacher/**` | `special:teacher:*` | 超管全量；老师仅自己 |
| 现有 | `/special/appointment/**` | `special:appointment:*` | 超管全量；老师仅 `teacher_id=自己` |

`special_teacher` 角色在 SQL 中挂上：老师查询/修改（自己）、预约查询/修改（自己）。**不**挂资源、机构、家长 CRM、用户角色、审核中心。超管仍 `*:*:*`。

老师即使用前端伪造请求，服务端按 `LoginHelper` 用户 + 档案 `user_id` 过滤。

## 6. 数据流（关键路径）

```
微信一键
  → xcx 登录（可能无手机号，角色含家长）
  → 浏览公开内容
  → 预约 / 我的  → 绑手机
       ├─ 号不存在：写到当前用户
       └─ 号已存在：合并到已有用户（可叠老师+家长），换 token

手机号注册
  → 验证码（微信授权号或短信）
  → 建用户或叠家长 → 登录 → currentRole=家长

后台新建老师
  → 手机号合并 → 角色+档案+初始密码
  → 老师用手机号密码登小程序或 PC
  → 小程序「我的」可切到家长（若已有家长）或先注册/绑手机叠家长
```

---

## 7. 错误处理

沿用 `R.fail` 文案，不新造错误码体系。§2 失败文案为准。

合并冲突（openid 已绑其他号、目标用户停用）：失败，不半合并。预约迁移与社交绑定在同一事务。

短信服务商未配置：发码接口返回「短信通道未开通」；不影响微信授权手机号。

## 8. 测试

### 自动化（实现时先测后码）

后端：

- 手机号合并：新号建用户；已有家长加老师；已有老师加家长；重复开通拒绝  
- `currentRole`：只能切已有角色；退出后会话失效  
- 老师数据范围：不能读/写别人档案和预约  
- 仅家长 + PC client 拒绝后台业务  
- 微信绑手机合并：预约 `user_id` 迁移、临时号停用、openid 唯一  

小程序：`pnpm --dir apps/mobile test:run`

- 角色缓存读写、失效回落  
- 登录页：手机号密码入口 + 微信入口（逻辑分支）  
- 预约列表分流纯函数（家长 vs 老师）  

后台：老师 payload（含手机号/密码）、角色开关请求体；现有 `teacher-payload` 测试保持通过。

### 手工验收

- 小程序：手机号注册家长 → 密码登录 → 微信一键（新微信）→ 强制绑手机  
- 后台建老师 → 小程序手机号登录 → 「我的」无切换（仅老师）→ 再注册/绑家长后出现切换  
- 切换后冷启动仍是上次角色  
- 老师登 PC：只有资料和预约；进不了资源/机构/用户角色  
- 超管用户角色页能给已有家长开通老师  
- 未过审老师不出现在小程序老师公开列表，但能登录改资料  
- 生产关闭测试验证码；未开短信时 H5 注册有明确提示

## 9. 实施顺序建议

拆实现计划时按可演示切片，不要一次铺开：
